# Журнал рішень: оновлення дизайну за новим прикладом

## Проблема
Порт на Astro відповідає попередній версії дизайну. У новому прикладі `.agents/propose/nordleaf.design/Main.dc.html` додано preloader, кастомний курсор, split-заголовки, curtain-reveal зображень, фото й бейдж у «O Nordleaf», рядки-тікер, кнопку «вгору» та ховання шапки при скролі. Поки порт не оновлено, сайт відстає від затвердженого вигляду. Якщо нічого не робити, замовник отримає сайт, що відрізняється від макета.

## Дано
- Дельта дизайну — лише `Main.dc.html` (+159/−21, `git diff --cached`); нових залежностей, шрифтів і зовнішніх хостів немає — перевірено: `git diff --cached`.
- Стилі порту — `src/styles/*.css`, ефекти — `src/scripts/effects.ts` (vanilla, `initReveal`, `initScrollEffects`, `initTilt`) — перевірено: `src/`.
- Тексти секцій — `src/content/site/*.yaml`, схеми — `src/lib/site-schemas.ts`, дзеркало — `public/admin/config.yml`; зображення hero/band мають поле `image` і плейсхолдер у `src/assets/placeholders/` — перевірено: `band.yaml`, `Band.astro`.
- `Base.astro` має `.prog`; `.pre`, `.cur`, `.totop` відсутні — перевірено: `Base.astro`.
- Збережені рішення порту, які не переглядаємо: `prefers-reduced-motion` вимикає ефекти, контент не залежить від JS, axe = 0 порушень, жодних нових зовнішніх хостів — перевірено: `PORTING_NOTES.md`.
- Фото в «O Nordleaf» у прототипі — crop єдиного фото (`.a1`); за ТЗ у порту потрібен плейсхолдер — перевірено: `PORTING_NOTES.md`, «Відхилення від дизайну».
- Доменна модель: окремої немає (статичний лендінг; змінюється лише презентація).

## Концепт рішення
**Обрано:** точковий порт дельти в наявну архітектуру (CSS по секціях, ефекти в `effects.ts`, контент через content collections).
**Чий:** згенеровано у воронці (концепт єдиний, без реальної альтернативи)
**Чому:** порт уже мапить дизайн 1:1, нова дельта лягає в ті самі шви.
**Відкинуто:**
- Заміна порту прототипом/React-рантаймом — суперечить вимогам ТЗ (без React, SEO, доступність).
**ADR:** ні — оборотна зміна презентації, без нових меж контекстів.

## Вектор
```
Main.dc.html (дельта) ──► styles/*.css (+ pre, cursor, split, clip, ticker, totop)
                     ├──► components/* (Preloader, Cursor, ToTop, Ticker, About-фото+бейдж)
                     ├──► scripts/effects.ts (курсор, ховання шапки, split/clip у IO)
                     └──► content: about.image (+imageAlt), site-schemas, admin/config.yml
```
- Межа зміни: презентація лендінгу; контракт `POST /api/contact`, воркери, CMS-структура секцій поза межами, крім нового поля фото About.
- Назви полів і дані лишаються в content collections; розмітку анімацій дає компонент.
- Нові скрипти додаються в наявний `effects.ts`, окремого бандла немає.

## Деталі
### Preloader
**Рішення:** як у дизайні: показується при кожному завантаженні (~2,2 с), hero-анімація стартує із затримками з прототипу (1,05 с і далі).
**Чому:** вибір розробника: вигляд 1:1 з макетом важливіший за LCP повторних візитів.
**Альтернатива:** раз за сесію (`sessionStorage`) — відкинуто розробником; без preloader — втрачає ключовий ефект.
**ADR:** ні — оборотно, чистий CSS.

## Відкриті питання
- LCP/CLS з preloader — виміряти після порту (Playwright/Lighthouse, як у `PORTING_NOTES.md`); якщо погіршення суттєве, повернутися до варіанта «раз за сесію».
- Футерний `big-word`: порт тримає текст у `::before` (`data-w`), бо axe ловить контраст навіть на `aria-hidden`-тексті, а нова split-анімація потребує літерних спанів у розмітці. Рішення (спани + виняток для axe чи анімація без спанів) — під час реалізації за результатом axe; якщо не вдасться без порушень, лишити статичний напис.

## Припущення
- Preloader повністю на CSS (як у прототипі), тож без JS він сам зникає; під `prefers-reduced-motion` додається явний `.pre{display:none}`, бо глобальне правило обнуляє лише тривалість, а `animation-delay` залишається, тож заставка висіла б 1,2 с. Не блокує.
- Фото About — нове поле `image` + `imageAlt` у `about.yaml`, схемі й `config.yml` за зразком hero/band; плейсхолдер у `src/assets/placeholders/` (`<Picture/>`, AVIF+WebP, lazy). Не блокує.
- Split-заголовки розбивають на `.sw/.sw-i` під час збірки Astro-хелпером; `h2` отримує `aria-label` із повним текстом, а спани `aria-hidden`; без JS текст видно. Не блокує.
- Кастомний курсор вмикається лише за `(pointer: fine)`, без `prefers-reduced-motion`; живе в `effects.ts`, нативний курсор не ховаємо (у прототипі теж). Не блокує.
- Ховання шапки при скролі, кнопка «вгору», тікер `.sv`, бейдж, shine, hover кроків переносяться 1:1; під reduced-motion тікер і прогрес-кільце статичні. Не блокує.
- Тікер `.sv` і preloader — `aria-hidden`, декоративні; чи ловить їх axe-контраст (як `big-word`), покаже перевірка після порту. Не блокує.
